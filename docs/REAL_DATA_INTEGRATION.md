# 真实数据嫁接顺序 v0.2

## Phase 0：先建立数据字典

招投标部门提供：

- 所有现用表；
- 每张表字段定义；
- 谁维护、何时维护；
- 原始来源；
- 哪些字段会后续变化；
- 哪些字段属于人工判断。

系统先建立 `Project ID / Entity ID / Source Pointer`，不急着自动写回。

## Phase 1：只读接入现有表

优先：

1. 盲投信息表；
2. 我司参与/未参与项目；
3. 竞对数据；
4. 项目期限/到期数据；
5. 报名、保证金等台账。

目标：搜索、分析和提醒先能用起来。

## Phase 2：官网监测

按可靠性分层：

`官方 API/RSS > HTTP > Playwright > Browser Agent > 人工`

每个来源接入前先定义健康阈值和失败兜底。

## Phase 3：自动回填

只对高置信度、可追溯字段开放自动写回：

- 项目名；
- 甲方；
- 地区；
- 公告时间；
- 原 URL；
- 中标单位/金额（实体匹配通过后）。

金额、关键截止日期、资格要求等可以先走“AI预填 + 人工确认”。

## Phase 4：文档解析与索引

Docling 解析 PDF/DOCX/XLSX；保存：

- 文本；
- 页码/章节；
- Source Pointer；
- Chunk；
- Embedding。

不无脑复制所有原始文件。

## Phase 5：决策参考和经验闭环

先 RAG + 规则 + 真实历史数据，不急着训练大模型。

重点积累：

- 项目分类修正；
- 未参与原因；
- 相似项目确认；
- AI评估修正；
- 报价复盘；
- 中标/失标真实原因。

数据稳定后再训练分类器、reranker 或小模型。
