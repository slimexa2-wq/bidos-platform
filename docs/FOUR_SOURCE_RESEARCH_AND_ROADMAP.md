## 一、四源深度调研矩阵

### 1. 本公司真实业务资料与定版四大铁律（`docs/FEATURE_IMPLEMENTATION_MATRIX.md` & `GAP_CLOSURE.md`）
- **BidOS 定版四大铁律**：
  1. 没有明确数据来源的功能，不进正式版本。
  2. 没有失败兜底的自动化，不允许静默运行（解析或提取低置信度必须显式进入 `待人工核验`）。
  3. **强制 Source Pointer 溯源**：没有 `Source Pointer`（精确到来源 URL/文件名、页码、章节、表格 Sheet+行列坐标、原文摘录）的关键 AI 结论，只能标记为“参考”。
  4. **人机职责边界**：AI 不替代“是否参与投标、最终报价、风险接受、正式提交”。
- **核心业务流闭环**：
  - **招投标机会与台账管理**：盲投新项目发现 → 自动填盲投表 → 更正公告 Hash/Diff 监控 → 中标公告实体匹配回填 → **项目结束日期前 90 天持续到期提醒（新招标公告匹配成功后自动解除并转为新机会）** → **投标保证金退回台账（应退日期前 3 天提醒 + 逾期高优持久事件 + 实际到账凭证核销）**。
  - **招标文件深度解析与合规矩阵**：资格要求、评分标准、废标条款（`★ / ▲ / 必须 / 应当 / 否则按无效标处理`）、外置化 `MATERIAL_RULES` 投标材料清单抽取（未命中规则表的长句自动归入 `unknown_requirements` 兜底，绝不硬套或漏检）。

### 2. 同类标杆商业产品对标
- **Lucius AI / DeepRFP（标书“粉碎机” RFP Shredder）**：将整本招标文件按强制性条款自动拆解为结构化 **合规审查矩阵（Compliance Matrix）**，逐条映射我方资质库/历史标书证据，自动标红“资质缺失/业绩不满足/时间冲突”等废标风险。
- **Loopio / Responsive (RFPIO)**：借鉴其企业证照与业绩案例知识库（Content Library）的**有效期动态监控**（如劳务派遣许可证、人力资源服务许可证、ISO 证书、审计报告、社保证明到期预警）与一键引用带 Source Pointer 的应答段落。
- **讯飞星火投标 / 百度招投标助手**：借鉴其针对国内政府采购网、公共资源交易中心公告的“更正公告差异高亮对比（变更前 vs 变更后条款级 Diff）”与“整标一致性检查（开标一览表大小写金额、工期、项目经理姓名全标书前后一致性校验）”。

### 3. 优秀开源项目借鉴
- **Docling (IBM)**：用于 PDF/DOCX/XLSX 招标文件的高保真结构化解析，保留章节层级树（Section Hierarchy）与跨页复杂评分表格。
- **RAGFlow (InfiniFlow)**：借鉴其针对招投标长文档的“模板感知分块（Template-based Chunking）”——将“投标人须知前附表”、“评标办法前附表”、“采购需求技术参数”作为独立语义单元切分，避免普通固定窗口切分截断表格或废标条款。

### 4. 学术论文与算法模型支撑
- **Hierarchical Document RAG with Citation Grounding**：在检索与抽取阶段强制绑定 AST/DOM 节点 ID（`doc_id + page_no + bbox/cell_ref + quote_hash`），生成后执行 **Claim-to-Source 反向蕴含校验（Entailment Verification）**，消灭金额、日期、资质等级幻觉。
- **Dual-Channel Disqualification Clause Detection（双通道废标项零漏检算法）**：通道 A（确定性正则 + 句法模态词规则树 `MATERIAL_RULES`）与通道 B（结构化 LLM 抽取）并行运行，取并集后对分歧项自动标记 `needs_human_review=True`，实现废标条款召回率趋近 100%。

## 二、分阶段功能完善与工程演进路线图

### Phase 1：双通道废标项粉碎机（RFP Shredder）与整标一致性检查器（`apps/`）
1. 完善招标文件解析与需求抽取管线：实现**废标条款与评分点双通道提取器（合规矩阵生成器）**，每条输出强制携带 `SourcePointer`（文件名、页码、章节、原文片段、置信度）及 `unknown_requirements` 零漏检兜底。
2. 新增**整标前后一致性检查器（Bid Consistency Checker）**：自动核验投标文件内的项目名称、项目编号、投标总价（大小写一致性）、分项报价汇总勾稽、服务期限/工期、拟派项目负责人姓名与身份证号在全文各章节是否 100% 一致。

### Phase 2：90 天项目到期事件引擎与保证金退回台账闭环加固
1. 强化 `EVENT_ENGINE_PERSISTENCE` 与 `EXPIRY_AND_BID_BOND_RULES`：完善 90 天到期预警持久事件、新公告实体匹配自动解除到期提醒、保证金应退日期前 3 天提醒与逾期升级告警的完整边界测试与 API。
2. 完善更正公告条款级 Diff 对比引擎（自动识别报名截止时间顺延、预算金额变更、资格条件变更并触发高优事件）。
