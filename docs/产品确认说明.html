招投标部门确认稿 · V0.1

BidOS：不改变成熟工作流，只让信息更快到人手里

表还是原来的表，官网还是原来的官网，文件还是原来的文件。系统在后台持续监测、索引、提取、关联和提醒；AI负责把真实数据与参考依据摆到桌面上，人负责核验、讨论和最终决策。

我们想解决的不是“多做一个系统”

真正的问题是：每天重复查网站、翻文件、复制粘贴、记截止时间、盯竞对、月末补数据，人的注意力被机械动作消耗。

自动化替人盯 · AI替人找依据 · 人负责决定

一、现有工作流不推翻

BidOS沿着现有招投标流程提供辅助，员工不需要重新学习一套业务逻辑。

三、每个环节只做该环节该做的事

避免“首页像提醒中心、提醒像项目详情、分析又像另一个首页”的重复设计。

1

盲投信息

新发现项目、AI自动提取字段、待核验、重点关注、原公告、源表对应位置。

2

报名管理

报名截止、资料清单、缺失材料、保证金/报名费状态、生成报名材料。

3

摘要评估

关键条款、资格、评分、相似项目、竞对历史、支持/谨慎依据、人工结论。

4

标书制作

章节进度、资料调用、历史优秀内容、AI辅助写作、格式与一致性检查。

5

结果复盘

中标/未中标、报价对比、失败原因、成功经验、下一次可调用的经验。

四、AI不是裁判，是“数据参谋”

当老板、负责人意见不一致时，AI不替任何人拍板，而是快速拉出历史数据、竞对、相似项目和原始证据。

例：这个项目应该高价还是压价？

支持较高报价甲方历史同类项目并非明显最低价导向；价格分权重约20%。查看历史公告 ↗
支持适度压价主要竞对近半年类似项目报价区间下移；我司过去有因价格分导致失标的案例。查看竞对数据 / 历史复盘 ↗
仍不确定主要竞对是否参与当前项目尚未确认。

AI应该输出什么？

事实 当前项目条款历史 相似项目竞对 参与/报价习惯经验 成功/失败原因证据 原公告/源表未知 待核实信息

AI只给参考思路与证据，不输出“必须报价多少”这种替人决策的指令。最终报价、是否参与、风险接受仍由项目负责人和管理层讨论决定。

五、所有数据都要“能回去”

不是制造第二套真假难辨的数据，而是让每个答案能快速回到第一手证据。

✓ 我们要做

  • 提醒直接带官网原公告。
  • Excel / 飞书表尽量定位到具体记录。
  • PDF尽量定位页码和条款。
  • AI回答显示引用来源。
  • 历史数据可搜索、可关联、可被下一次判断调用。

× 我们不做

  • 不把几十张表全复制到新系统。
  • 不让员工重复录入已有数据。
  • 不把天气、装饰图、无行动价值KPI塞进首页。
  • 不让AI黑盒直接替人决定。
  • 不因为“有AI”就改变成熟工作习惯。

六、PC与手机是一套系统

信息、功能、权限一致；只是根据屏幕改变排版。后台统一运行在云服务器或专用服务器。

同一后端同一数据库同一索引同一权限同一业务逻辑PC多栏手机纵向

七、请部门先确认这些方向

先确认工作方式和功能边界，再进入真实数据接入和细节开发。

1. 保留盲投 → 报名 → 评估 → 标书 → 结果复盘的现有流程未确认
2. 原表、原文件、原官网继续使用，BidOS负责辅助与联动，不重新造一套数据未确认
3. 系统替人盯新公告、中标结果、项目到期、竞对变化、保证金等事件未确认
4. AI提供真实数据、历史经验和参考依据，人负责讨论和最终决策未确认
5. 每条重要信息都尽量能回到官网原文、原文件页码或源表具体位置未确认
6. UI坚持实用、好用、直观：页面职责不重复，无关信息坚决不加未确认
